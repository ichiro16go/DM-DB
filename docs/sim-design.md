# デュエル・マスターズ AI シミュレーション 設計（Phase 1）

## 目標

- 40枚のバニラクリーチャーのデッキ同士で、AI 対 AI の対戦を最後まで自動で行う
- 終わったあとに、人間が**勝敗**と**棋譜**をファイルで確認できる
- 同じデッキ・乱数のシード・行動の列からは、同じ対戦を必ず再現できる

決めたこと：AIはランダムと定石（ルールベース）の2種類（Claude などは後から差し込める形だけ用意）／棋譜はファイルで出す（Web の閲覧画面は次のフェーズ）／デッキは DB のバニラから自動生成／置き場所は `src/sim/`。

## Phase 1 のルール

| 段階 | 内容 |
|---|---|
| 準備 | 40枚をシャッフル、シールド5枚、手札5枚。先攻・後攻はランダム |
| ターン | アンタップ → ドロー（先攻の1ターン目はなし）→ マナチャージ（任意、1枚）→ メイン（召喚）→ 攻撃 → 終了 |
| マナ | コスト分のマナをタップ。その中にカードの各文明が最低1枚必要（無色は不要）。多色カードはタップ状態でマナへ |
| 召喚 | 出したターンは攻撃できない（召喚酔い） |
| 攻撃 | アンタップ状態で召喚酔いでないクリーチャーが、相手プレイヤーか、相手のタップ状態のクリーチャーを攻撃。攻撃したクリーチャーはタップ |
| バトル | パワーの低い方を破壊。同じなら両方破壊 |
| ブレイク | シールドを1枚、持ち主の手札へ（どのシールドかは攻撃側が選ぶ） |
| 勝敗 | シールド0枚のプレイヤーへの攻撃が通ると、攻撃側の勝ち。山札が0枚になったプレイヤーは負け。上限ターン数で引き分け |

すべての数値は `src/sim/config.ts` の1か所にまとめる（デッキ枚数、シールド枚数、初期手札、先攻1ターン目のドロー、マナチャージの回数、上限ターン数など）。後から数値だけ変えて試せるようにするため。

## 構成

```
src/sim/
  config.ts       ルールの数値（上の表）
  cards.ts        シミュ用のカード定義 SimCard（DB のカードから変換）
  rng.ts          シード付き乱数（再現性のため。Math.random は使わない）
  state.ts        対戦の状態（ゾーン、マナ、タップ、召喚酔い、手番、フェーズ）
  actions.ts      行動の型と、合法手の列挙 legalActions(state)
  engine.ts       行動の適用 apply(state, action) → 出来事 events。勝敗判定もここ
  view.ts         プレイヤーから見える情報 observe(state, player)（相手の手札と伏せたシールドは枚数だけ）
  agents/
    agent.ts      エージェントの共通の形 choose(view, legalActions) → action
    random.ts     合法手から無作為に選ぶ（ルール確認用）
    greedy.ts     定石（下記）
  deckgen.ts      DB のバニラから、文明とコスト配分を指定してデッキを自動生成
  log.ts          棋譜：JSON と日本語テキスト
  runner.ts       1局を最後まで回す。複数局と集計
  cli.ts          npm run sim
```

- **エンジンは外部の入出力をしない**（ファイル・ネットワーク・時刻・`Math.random` を使わない）。テストしやすく、再現性が保てる。
- **カード定義** `SimCard = { id, name, civs, cost, power, type, abilities: [] }`。Phase 1 では `abilities` は空。Phase 2 以降で能力を足す入口になる。DB とは変換関数1つでつながり、エンジンは DB を知らない。
- **ゾーン**：山札・手札・マナ・バトルゾーン・シールド・墓地。カードは対戦ごとの通し番号（インスタンスID）で追う。同じカードが4枚あっても区別できる。

## 行動（合法手）

手番のプレイヤーは、その時点の合法手の一覧から1つを選ぶ。

| フェーズ | 行動 |
|---|---|
| マナチャージ | `charge(手札のカード)` / `skipCharge` |
| メイン | `summon(手札のカード, 支払うマナ)` / `endMain` |
| 攻撃 | `attack(攻撃するクリーチャー, 相手プレイヤー or 相手のタップ状態のクリーチャー)` / `endAttack` |
| ブレイク | `breakShield(シールドの番号)`（攻撃側が選ぶ） |

- **マナの支払い**：組み合わせが多くなりすぎないよう、合法手の一覧では「どのカードを召喚するか」だけを並べる。どのマナを使うかは支払いの補助関数が自動で決める（後の手番で必要になる文明を残す方針）。エージェントが支払いを細かく指定することもできる。
- 一覧が空になる局面は作らない（どのフェーズにも「終える」がある）。

## エージェント（AI）

共通の形：`choose(view, legal) → action`。`view` は、そのプレイヤーに見える情報だけ（人間と同じ条件にして、後で強さを公平に比べられるようにする）。

- **ランダム**：合法手から無作為に選ぶ。何千局も回して、ルールの抜けや無限ループを見つける用。
- **定石**（ルールベース。判断の重みは設定値にして調整できるようにする）：
  - マナチャージ：マナが少ないうち（例：6枚まで）は毎ターン置く。手札で一番出しにくいカード（重い、文明が合わない）から置く
  - 召喚：出せる中で一番重いもの。同じなら パワーの高い方
  - 攻撃：
    - 相手のタップ状態のクリーチャーに一方的に勝てるなら倒す
    - 相手の反撃で一方的に負けない状況なら、シールドを割りに行く
    - 相手のシールドが0枚で攻撃できるなら、とどめを刺す
- 後から同じ形で、探索型のAI（モンテカルロ木探索など）や、Claude に手を選ばせるAIを差し込める。

## 棋譜と結果

`npm run sim -- --games=100 --seed=1 --deck-a=火:2-7 --deck-b=水:2-7 --agent-a=greedy --agent-b=random`

出力先 `data/sim/<日時>/`：

- `summary.json`・`summary.txt`：対戦数、各プレイヤーと先攻・後攻の勝率、平均ターン数、勝ち方の内訳（とどめ／山札切れ／引き分け）
- `game-0001.json`：再現用の情報（ルール設定・シード・両デッキ・エージェント）と、行動の列と出来事の全記録
- `game-0001.txt`：人が読む棋譜。例：

```
T3 先攻 A（マナ3・手札4・シールド5 ／ 相手 シールド4）
  マナチャージ《ゴーレム X》
  召喚《ドラゴン Y》（コスト3・パワー3000）
  攻撃《ボーグ Z》→ プレイヤー：シールドをブレイク（相手のシールド残り3）
```

棋譜はすべてのカードを公開して書く（観戦者の視点）。JSON からエンジンで同じ対戦を再生し、出来事が一致することをテストで確かめる。

## デッキの自動生成

- 対象：DB のバニラクリーチャー（能力なし。オリジナルで使えるもの）。いまは単色181種
- 指定：文明（1〜2色）、コストの配分（例：2コスト8枚・3コスト10枚 …、省略時は既定のカーブ）、1種類4枚まで、シード
- 使うカードの一覧はデッキに書き込むので、DB が更新されても過去の対戦を再現できる

## テスト

- ルールの単体テスト：同じパワーで相討ち、召喚酔い、多色はタップでマナへ、文明のないマナでは払えない、シールド0枚で勝ち、山札0枚で負け、先攻1ターン目にドローしない
- 再現性：同じシードと行動の列で、棋譜が完全に一致する
- 大量対戦：ランダム同士で数千局。例外が起きない、必ず終わる、カードの総数（40枚×2）が常に保たれる
- 定石がランダムに大きく勝ち越すこと（定石の判断が機能している確認）
